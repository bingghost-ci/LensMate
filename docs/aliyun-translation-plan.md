# LensMate 阿里云实时翻译方案与工作原理

更新日期：2026-10-24。适用设备：iPhone 与 Meta 智能眼镜。首批语言：中文、英文、泰语。

完整语音版本计划采用**阿里云实时语音识别 + 阿里云文字翻译 + iPhone 系统朗读 + 眼镜蓝牙播放**。云端统一使用阿里云百炼；DeepSeek、Gemini 等服务暂不作为第一版依赖。

当前已具备可构建的 iOS App，并完成第一批「中英泰文字翻译＋iPhone 本地朗读」开发及非 UI 测试；实际接口、UI 与听感待验收，详见[本批使用说明](text-translation.md)。下文的持续收音、ASR 和眼镜专用路由仍是后续方案。[打开交互式工作原理图](translation-flow.html)，可切换语言、收音和播放设备，逐步查看数据流，并估算用量费用。HTML 可直接在浏览器打开；演示无需联网，也不会录音或调用付费 API。

## 设备和服务怎样分工

| 组成 | 负责什么 | 需要明确的边界 |
|---|---|---|
| Meta 眼镜 | 作为蓝牙音频设备，采集声音、播放译音 | 实际麦克风与扬声器路由需要真机确认；蓝牙已连接不代表 App 正在用眼镜麦克风 |
| iPhone 上的 LensMate | 管理音频、发送云端请求、整理识别结果、选择翻译方向、显示译文、生成语音 | 手机持续参与工作；首轮使用保持 App 在前台 |
| 阿里云实时识别 | 将音频转换成源语言文字 | `qwen3-asr-flash-realtime`，按输入音频时长计费 |
| 阿里云翻译 | 将源文字转换成目标语言文字 | `qwen-mt-flash`，按输入与输出文字 Token 计费 |
| iPhone 系统语音合成 | 把目标语言文字生成可播放的音频 | 不需要外部 TTS API Key；三语可用音色及离线合成要在手机上确认 |

Qwen-ASR 和 Qwen-MT 的官方支持列表覆盖中、英、泰。语言覆盖说明接口可以接入，不代表已经验证当地口音、街头噪声或专有名词的准确率。[语音识别说明](https://help.aliyun.com/zh/model-studio/asr-model) · [Qwen-MT 翻译说明](https://help.aliyun.com/zh/model-studio/machine-translation/)

眼镜播放的是**iPhone 生成并传来的音频**。方案不依赖第三方将任意文本交给眼镜内部朗读的接口，也不在眼镜上安装或运行大模型。苹果提供的 [AVSpeechSynthesizer](https://developer.apple.com/documentation/avfaudio/avspeechsynthesizer) 用于手机侧文字转语音；实际音频路由可参考 [OpenVision 音频会话实现](https://github.com/rayl15/OpenVision/blob/v2.14.0/OpenVision/Services/Audio/AudioSessionManager.swift)。

## 一句话从收音到播放

以听到泰语、希望听见中文为例：

1. **采集声音。** 选择眼镜麦克风，或将 iPhone 放在对方附近使用手机麦克风。后者是面对面交流的收音候选方案。
2. **手机整理音频。** LensMate 从 iOS 音频会话读取数据，按识别服务要求转换采样率、声道和编码，通过网络持续发送音频片段。
3. **阿里云识别原文。** ASR（语音识别）返回泰语文字。流式识别中的临时文字可能修订，手机可以显示它，但不应把每次修订都立即翻译并重复朗读。
4. **手机确定可翻译的片段。** 等待服务确认的短句或稳定语义片段，为其分配编号，再发起独立的翻译请求。
5. **阿里云返回译文。** Qwen-MT 接收源文字和语言方向，返回中文。识别和翻译是两个接口，由手机连接起来，不是两个云模型自动相互调用。
6. **手机生成声音。** LensMate 显示译文，选择中文系统音色，交给 iPhone 语音合成。完整短句按顺序进入播放队列。
7. **眼镜播放。** iPhone 把合成音频通过蓝牙发送给眼镜扬声器。用户听见中文，同时可在手机查看原文和译文。

```text
眼镜或手机麦克风
    │ 音频
    ▼
iPhone 音频处理 ──音频──▶ 阿里云 ASR
    ▲                         │
    └────────源文字───────────┘
    │ 手机确认短句
    └──源文字 + 语言方向──▶ 阿里云 Qwen-MT
    ▲                         │
    └────────目标语言译文──────┘
    │
iPhone 系统朗读 ──音频──▶ 眼镜或手机扬声器
```

“实时”意味着持续接收音频、逐段输出译文。仍然需要断句、网络、模型处理和语音生成，不是对方每说一个字就能立即得到完整准确的翻译。过短的片段可能缺少语境；过长的片段会增加等待时间。

## 三种日常使用方式

| 用法 | 输入与翻译方向 | 输出与操作 |
|---|---|---|
| 听懂对方 | 英语或泰语 → 中文；选择实际更清楚的麦克风 | 中文通过眼镜播放，原文与译文留在手机屏幕 |
| 替我表达 | 中文 → 英语或泰语 | 向对方展示手机译文；需要声音时明确切换为手机扬声器 |
| 双向交流 | 固定一对语言，轮流切换方向 | 第一版用按钮切换说话方；验证后再研究自动识别方向 |

中文、英文、泰语之间的六个翻译方向均纳入验证。一次请求仍然有明确的目标语言；“支持三语”不代表一次会话会自动知道每句话应该译给谁听。

眼镜靠近佩戴者，对面说话人的声音未必最清楚。手机麦克风收音、眼镜播放的组合也受 iOS 音频路由约束，需要实测后才能作为可靠选项。第一版不承诺同时向眼镜和手机播放不同的声音。

## API Key 和联网原理

**API Key 是调用服务的凭证，Token 是模型计算和计费的单位。** 同一地域和业务空间下，权限允许的一把百炼 API Key 可以调用上述两个模型；识别与翻译的费用仍分别累计。北京与新加坡的 Key、接入地址和模型列表不能跨地域混用。[API Key 官方说明](https://help.aliyun.com/zh/model-studio/get-api-key/)

后续按[OpenVision 二次开发方案](openvision-development-plan.md)保留原项目功能，新增独立翻译模式。下述凭据与数据范围针对新增翻译链，不限制原有助手可用的模型和工具；[源码审计](security-audit-2026-10-24.md)仍保留供查阅。

正式接入优先采用如下凭据路径，需先确认所选接口支持：

```text
自己的凭据服务保存长期 API Key
    ↓ 根据账号或设备鉴权，申请短期凭据
iPhone 获取短期凭据
    ↓ 使用对应地域的地址
iPhone 直接连接百炼识别与翻译服务
```

阿里云提供最长 1,800 秒的临时 API Key。接入时核对其对所选接口的支持和权限，提前刷新，处理会话重连。支持直连时，凭据服务不必转发每段音频；不支持的接口由自有服务端代理，并披露它经手的数据、关闭正文日志。长期 Key 不放进 App 源码、网页或日志。此前讨论的“在 App 填 Key”是个人原型的简化配置思路，必须写入 Keychain，失败时不能退回普通配置文件。

本方案需要联网：音频上传阿里云做识别，识别后的文字再上传做翻译。手机本地朗读不意味着整条链路离线。拟定默认不保存原始录音，历史记录由用户主动开启；阿里云侧的数据处理与保留以对应服务条款和账号设置为准。

## 费用怎样计算

以下使用 2026-10-23 核对的百炼公开原价，不含活动和免费额度，币种为人民币。

| 项目 | 北京地域 | 新加坡地域 |
|---|---:|---:|
| `qwen3-asr-flash-realtime` 输入音频 | ¥0.00033 / 秒 | ¥0.00066 / 秒 |
| `qwen-mt-flash` 输入文字 | ¥0.70 / 百万 Token | ¥1.174 / 百万 Token |
| `qwen-mt-flash` 输出文字 | ¥1.95 / 百万 Token | ¥3.596 / 百万 Token |
| iPhone 系统朗读 | 无云端 TTS 调用费 | 无云端 TTS 调用费 |

公式：

```text
模型费用 = 上传音频秒数 × ASR 单价
         + 翻译输入 Token ÷ 1,000,000 × 输入单价
         + 翻译输出 Token ÷ 1,000,000 × 输出单价
```

**预算示例假设：** 每小时上传 3,600 秒音频，翻译累计输入 50,000 Token、输出 20,000 Token。这是可替换的预算假设，不是实测的日常讲话用量。上下文、重复片段或重试都可能改变实际用量。

| 示例用量 | 北京地域 | 新加坡地域 |
|---|---:|---:|
| 1 小时 | ¥1.26 | ¥2.51 |
| 每天 30 分钟，30 天 | ¥18.93 | ¥37.60 |
| 每天 60 分钟，30 天 | ¥37.86 | ¥75.20 |

费用不含凭据服务、手机流量等开销。按实际上传音频统计，不应把静音都当成免费；端点计费的取整规则也会影响短请求费用。HTML 估算器使用同一组假设，停止翻译时应停止上传并结束云端会话。[模型价格](https://help.aliyun.com/zh/model-studio/model-pricing)

如主要在泰国使用，将新加坡作为网络测试候选，同时比较实际可用的北京节点；节点位置本身不能保证延迟更低。

## LiveTranslate 备选路线

阿里云还提供 `qwen3.5-livetranslate-flash-realtime` 等实时语音翻译接口，官方中、英、泰均支持文本和音频输出。它可以把“上传音频 → 收到译文与译音”合并为一个会话，手机收到译音后直接播放，不再经过本地 TTS。[实时语音翻译文档](https://help.aliyun.com/zh/model-studio/qwen3-5-livetranslate-flash-realtime)

| 比较项 | 第一版省钱方案 | LiveTranslate 备选 |
|---|---|---|
| 云端链路 | ASR + Qwen-MT 两个接口 | 一个实时翻译会话 |
| 语音生成 | iPhone 系统朗读 | 阿里云生成译音 |
| 调节能力 | 可分别调整断句、翻译和本机声音 | 按实时翻译接口提供的参数调节 |
| 费用 | 音频识别 + 文字翻译 | 按输入音频、输出文字与音频等分别计费 |
| 体验判断 | 测短句准确率、等待与队列积压 | 使用相同语料和网络对照测试 |

上面的每小时费用只适用于第一版省钱方案，不能套用到 LiveTranslate。两者谁更快、更自然，需要在实际设备和网络下比较。暂不因为支持语音就改用普通聊天模型充当翻译接口。

## 完整语音版本计划的使用方式

1. 在 Meta AI App 完成眼镜配对，先确认普通蓝牙播放可用。
2. 安装 LensMate，完成所选百炼地域和凭据配置；首次使用授予麦克风权限。
3. 选择源语言和目标语言，例如“泰语 → 中文”。
4. 确认输入设备与输出设备，播放测试音，检查实际麦克风来源。
5. 点“开始翻译”。App 前台持续接收音频，手机显示原文与译文，眼镜自动逐句播报。
6. 需要回复时切换方向，按需把声音输出切到手机；完成后点“停止”，结束录音、请求与播放。

第一轮不使用眼镜相机。Meta DAT 的相机、语音唤起、锁屏和后台能力以后分别评估，避免把纯语音翻译的使用前提扩大。眼镜仍需原有配对；本方案不替换 Meta AI 的系统唤醒词或固件。

## 完整语音版本的后续开发和验收顺序

| 顺序 | 工作 | 必须得到的结果 |
|---|---|---|
| 1 | 验证 iOS 蓝牙音频路由 | 分别确认眼镜输入、眼镜输出、手机输入；不能只看连接状态 |
| 2 | 打通 ASR 和 Qwen-MT | 三语六方向有原文与译文，临时识别结果不会重复提交 |
| 3 | 加入系统朗读 | 三语音色可用；记录能否离线朗读；检查目标语言是否匹配 |
| 4 | 完成播放和取消管理 | 播放队列有上限；切换方向和停止后，旧请求结果不会继续播报 |
| 5 | 处理回声与打断 | 播放译音不会被再次当成新讲话翻译；必要时采用轮流听说模式 |
| 6 | 测真实交流 | 同一副眼镜、同一网络，测试餐饮、购物、出行语料以及金额、数字、否定句和地名 |
| 7 | 再测后台与恢复 | 锁屏、切 App、来电、蓝牙断开、网络恢复和凭据过期分别验证 |

每个方向先准备至少 10 句固定短句。记录说话结束、识别结果确认、翻译请求、译文到达和首段实际音频播放时间；以“说完到听见有效译音”衡量等待，不把提示音算成首个结果。输出 P50、P95、正确率、实际费用和连续使用 15 分钟后的发热与电量记录。暂不写入未经实测的延迟保证。
