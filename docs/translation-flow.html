1 / 7 · 先采集声音

眼镜麦克风采集对方的说话声，再通过蓝牙交给 iPhone。对面说话人离眼镜较远时，也可以尝试手机麦克风。

这是原理演示，不会录音或调用 API，播放节奏不代表真实延迟。麦克风与扬声器组合要按 iOS 实际音频路由验证；手机麦克风配眼镜播放也需要实测。

眼镜为什么能把文字“读出来”？

译文→iPhone 合成音频→蓝牙传给眼镜

真正完成文字转语音的是 iPhone。眼镜收到的是可以直接播放的声音，手机仍然需要在场。手机也会显示原文和译文。

中文、英文、泰语分别选择匹配的系统音色，必要时先下载声音；是否能离线合成，以你的手机实际可用音色为准。

为什么不会瞬间翻译完？

等待来自断句、网络、识别、翻译和播放缓冲。先听到足够的语义，才有可能翻得准确；片段太短会丢上下文，太长则会等得更久。

第一版逐短句翻译和播放。需要实测“说完到听见有效译音”的时间，并处理译音被麦克风再次收进去的回声问题。

02 / 费用

主要按听了多久付费

识别按音频秒数，翻译按文字 Token；手机朗读不增加云端 TTS 费用。

¥37.60/ 月，模型费用估算
语音识别 ¥35.64文字翻译 ¥1.96每小时约 ¥2.51

这个数字怎样得出？

预算假设：每小时上传 3,600 秒音频，翻译输入 50,000 Token、输出 20,000 Token。文字用量是示例假设，并非日常讲话的实测值。

每小时：3600 × 0.00066 + 0.05 × 1.174 + 0.02 × 3.596

不含重试、凭据服务和流量等费用，不计免费额度。静音如果仍被上传，也不能直接当成免费。这里只计算省钱方案。核对官方价格 ↗

03 / 两条可选路线

统一阿里云，也有不同组合

第一版：识别 + 翻译 + 手机朗读优先实现

音频 → 阿里云识别 → 手机断句 → 阿里云翻译
→ 手机生成声音 → 眼镜播放

云端使用 qwen3-asr-flash-realtime 和 qwen-mt-flash。可以分别调节断句、翻译和本机声音，上面的估算适用于这条路线。

备选：LiveTranslate 直接生成译音

音频 → 阿里云实时翻译
→ 手机收到译文与译音 → 眼镜播放

如 qwen3.5-livetranslate-flash-realtime，支持中英泰文本和音频输出。另有音频生成费用，不能套用上面的价格；实际等待和自然度要对照测试。

04 / 使用方式

App 做成后，你只需选方向并开始

以下是目标使用流程；LensMate 当前还没有可安装 App。

  1. 配对眼镜，准备服务

    在 Meta AI App 完成配对，配置百炼地域和模型访问凭据。

  2. 选语言，确认实际收音与播放设备

    听懂对方：泰语或英语 → 中文，眼镜播放。替我表达：中文 → 外语，向对方展示手机译文或切换手机外放。

  3. 点开始，逐句听译音

    首轮保持 App 在前台。原文与译文出现在手机，声音按顺序自动播报。

  4. 结束时点停止

    同时停止录音、云端会话与播放，取消尚未完成的翻译。

一把 Key，授权多个模型

API Key 是调用服务的凭证；Token 是计算和计费单位。同一地域和业务空间内，权限允许的 Key 可用于识别和翻译，费用分别计算。

后端保管长期 Key→手机取短期凭据→连接百炼

正式接入使用短期凭据，长期 Key 不写进 App。凭据服务不必转发音频；Key 与接入地址要使用同一地域。

语音和文字会发往阿里云处理，因此这套方案需要网络。手机本地朗读不代表全程离线。

需要真机验证哪些事情？
  • 眼镜麦克风和扬声器是否被 App 实际使用，以及手机收音配眼镜播放的组合。
  • 三语识别、翻译和音色；重点检查金额、数字、否定句、地名及嘈杂环境。
  • 播放译音时的回声、队列积压、打断与停止后的旧结果。
  • 说完到听见译音的 P50 / P95、连续使用的耗电和费用。
  • 锁屏、切 App、来电、断网和蓝牙重连。首版不承诺锁屏可持续使用。
还需要摄像头、Meta AI 模型或 DeepSeek 吗？

纯语音翻译不需要眼镜摄像头，也不需要 Meta AI 模型或 DeepSeek 参与推理。Meta AI App 仍用于原有设备配对。这套方案不替换系统唤醒词，不在眼镜上运行大模型；按无镜内显示屏的设备设计，文字显示在手机。
